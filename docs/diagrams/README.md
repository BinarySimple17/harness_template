# Diagrams — диаграммы

Диаграммы хранятся **текстом (mermaid)** прямо в репозитории — ревьюятся в PR, как код, рендерятся на GitHub без внешних инструментов. Экспорт в картинки не ведётся (устаревает моментально).

## Что здесь лежит

| Файл | Назначение | Когда обновлять |
|---|---|---|
| [er-data-model.md](er-data-model.md) | **Каноническая модель данных (ER)** — сущности, связи, инварианты | Любое изменение схемы — в том же PR, что и миграция |
| [c4-context.md](c4-context.md) | Контекст (C1) и контейнеры (C2) — топология системы | Изменение топологии/новая деплой-единица |
| `sequence-<сценарий>.md` | Sequence-диаграммы ключевых сценариев | По мере появления сценариев (3+ компонента или асинхронность) |

## Соглашения

1. Один файл — одна диаграмма; заголовок файла = тип диаграммы.
2. Изменение диаграммы, меняющее архитектурное решение, — сначала ADR (`docs/adr/`), потом диаграмма.
3. В каждой диаграмме — блок «Чтение схемы»/комментарии: решения, неочевидные из картинки, объясняются словами (инварианты, приоритеты, границы владения).
4. Модель данных (`er-data-model.md`) согласована с `docs/api/openapi.yaml` (схемы ответов) — расхождение считается багом документации.
