# API Contract — OpenAPI

`openapi.yaml` в этой папке — **контракт API проекта** (single source of truth по внешнему HTTP-поверхности).

## Правила работы с контрактом

1. **Spec-first:** изменение API начинается правкой `openapi.yaml`, затем реализация — в том же коммите (правило «no stale docs» из `AGENTS.md`).
2. Каждое изменение контракта отражается в реестре ADR, если оно меняет архитектурное решение (версионирование, аутентификация), — см. `docs/adr/README.md`.
3. Обратная совместимость: ломающие изменения требуют новой версии пути (`/v2/...`) или явного ADR.
4. Примеры в `examples:` держать актуальными — агенты используют их как образец ответа.

## Как валидировать

```bash
npx --yes @redocly/cli lint docs/api/openapi.yaml   # линт + валидация схемы
```

Можно добавить эту команду в `init.sh`/`Makefile`, если API — часть верификации проекта (`ЗАПОЛНИТЬ` в ветке вашего стека).

## Что здесь лежит

| Файл | Назначение |
|---|---|
| `openapi.yaml` | Контракт API (OpenAPI 3.1) — заполняется по подсказкам `ЗАПОЛНИТЬ:` |

Подписи/схемы аутентификации, модели ошибок и пагинация — в `components:`; каждый эндпоинт — с `operationId` (по нему генерируются клиенты и трейс-спаны).
