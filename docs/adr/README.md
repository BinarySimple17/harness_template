# ADR — Architecture Decision Records

Индекс архитектурных решений проекта. Формат и правила — по образцу [walkinglabs/learn-harness-engineering](https://github.com/walkinglabs/learn-harness-engineering) и практики ADR (Michael Nygard).

- **Что сюда попадает:** значимые архитектурные решения — выбор технологий, модели данных, границы сервисов, протоколы безопасности. Один ADR = одно решение.
- **Что НЕ сюда:** оперативные решения сессий (журнал `DECISIONS.md` в корне) и факты (они — в `docs/ARCHITECTURE.md` и `docs/diagrams/`).

## Как заводить новый ADR

1. Номер — следующий по порядку; файл — `ADR-0NN-краткое-имя.md` в этой папке.
2. Скопируйте [ADR-TEMPLATE.md](ADR-TEMPLATE.md), заполните секции по подсказкам `<!-- ЗАПОЛНИТЬ: ... -->`.
3. Формат — как в шаблоне: заголовок, **Статус** (с датой и версией), контекст, альтернативы с trade-off, решение, последствия, revisit-триггеры.
4. Изменение уже принятого ADR — **новая версия в том же файле** с датой (история версий — в поле «Статус»), не тихая правка.
5. Решение, меняющее модель данных, — синхронно обнови `docs/diagrams/er-data-model.md`; меняющее API — `docs/api/openapi.yaml` (тот же PR).
6. Добавь строку в реестр выше.
