# Solution — план-сессий и канон исполнения

Уровень планирования harness для многосессионной разработки. Разделение ролей:

- **`feature_list.json`** (корень) отвечает на вопрос «**ЧТО** делаем» — атомарные фичи с верификацией;
- **`solution/`** отвечает на вопрос «**КАК** работаем» — на какие сессии разбит проект, кто владелец, что является каноном и где фиксируются противоречия.

## Что здесь лежит

| Файл | Назначение |
|---|---|
| [sessions.md](sessions.md) | **Индекс**: план-сессий (таблица), владельцы треков, карта владения файлами, граф зависимостей, вехи, «Текущее состояние» |
| [sessions/S00_session.md](sessions/S00_session.md) | **Канон проекта**: стек, порты, контракты стыков, архитектура кода, запреты, процесс. Источник истины при любом конфликте |
| [sessions/TEMPLATE_session.md](sessions/TEMPLATE_session.md) | Шаблон рабочей сессии (копируется под новый ID) |
| [FIXES.md](FIXES.md) | Журнал устранения противоречий канона (документ ↔ документ, документ ↔ код) |

## Жизненный цикл сессии

1. **Планирование:** скопировать [TEMPLATE_session.md](sessions/TEMPLATE_session.md) под ID (`<трек><NN>_session.md`), заполнить шапку/предусловия/задачи с самопроверками, добавить строку в таблицу `sessions.md` и в граф зависимостей. Зависимости сессии = закрытые сессии; в шапке — поле **«Фичи»** с ролью сессии: **«закрывает»** (финальная сессия фичи) или **«продолжает»** (промежуточная). Одна фича может занимать несколько сессий — закрывает ровно одна; фичи-зависимости к старту сессии должны быть в `passing`.
2. **Исполнение:** агент-исполнитель читает S00 (канон) → свою сессию → работает по правилам `AGENTS.md`. Задача закрывается только после ✅ Самопроверки.
3. **Закрытие (clock-out по `AGENTS.md`):** критерии приёмки отмечены, отчёт по сессии заполнен (Сделано / Отклонения от плана / Перенесено), статусы обновлены в шапке сессии и в `sessions.md`, «Текущее состояние» переписано, `progress.md` обновлён, коммит. Фичи: сессия-«закрывает» проводит `make verify-feature F=<id>` для каждой своей фичи; сессия-«продолжает» оставляет фичу `active` с allowlist в clean-check (`bash scripts/clean-state-check.sh . <id>`) — продолжение зафиксировано в `progress.md`.

## Приоритет источников при конфликте

1. `AGENTS.md` — правила работы агента (harness);
2. **S00** (`sessions/S00_session.md`) — канон проекта: стек, порты, контракты, запреты;
3. `docs/adr/` — архитектурные решения;
4. `docs/` — свёртки (ARCHITECTURE.md, ER-модель, OpenAPI);
5. рабочие сессии `solution/sessions/` — история исполнения.

Противоречие между любыми источниками (или между документом и кодом) — не правится тихо: запись в [FIXES.md](FIXES.md), решение владельца, синхронная правка всех затронутых мест. Файлы закрытых сессий не переписываются — это исторические записи.

## Обнаруженное вне скоупа

Всё найденное по ходу сессии, что не входит в её скоуп, — в `solution/backlog.md` (завести при первом упоминании; формат: `BL-NN` — описание, сессия-источник, приоритет). То, что влияет на приёмку текущей сессии, остаётся в сессии, а не уходит в беклог.
