## Правила для исполнителя (все сессии)

1. **Прогресс:** пункт без `[x]` — не сделан. Каждый Task закрывается только после ✅ Самопроверки; чекбоксы Предусловий/Задач/Критериев отмечаются `[x]` по факту. Статус в шапке сессии и в индексе `solution/sessions.md` обновляется; при закрытии сессии — «Текущее состояние» индекса, `progress.md`, `feature_list.json` (End of Session — `AGENTS.md`).
2. **Верификация — гейт каждого шага:** нельзя заявлять выполнение без прогона верификации (`make check` / `./init.sh` / тесты); evidence (команда + вывод) — в отчёт сессии. Фича из `feature_list.json` закрывается только через `make verify-feature F=<id>`, не правкой state руками. Фича может занимать несколько сессий: ровно одна (финальная) закрывает её через `make verify-feature`; промежуточные сессии оставляют её `active` с allowlist в clean-check (`bash scripts/clean-state-check.sh . <id>`), фиксируя продолжение в `progress.md` и «Текущем состоянии» индекса.
3. **API-дисциплина:** создание/изменение HTTP-эндпоинта = правка `docs/api/openapi.yaml` (spec-first) + запрос с тестами (Postman/newman или аналог проекта) + прогон. Эндпоинт без теста = Task не закрыт.
4. **Секреты:** все параметры через `infra/.env` (не коммитится); `.env.example` коммитится; дефолтов секретов в коде нет; обязательные переменные валидируются на старте (fail-fast).
5. **Схема БД — только через миграции.** Ни один сервис не создаёт таблицы `CREATE TABLE`-кодом, init-скриптами или ручным SQL. Новая миграция = новый файл; правка уже применённой — запрещена; сервис-владелец поднимает свою схему при старте (идемпотентно, до поднятия HTTP).
6. **Слои кода:** `presentation → application → domain (протоколы) ← infrastructure`; зависимости направлены строго внутрь, драйверы хранилищ и HTTP-клиенты — только в `infrastructure`; сборка зависимостей — в composition root (единственное место). Env — только через `Settings` (никаких `os.environ` в бизнес-коде).
7. **Тесты — модульно.** Один файл = один компонент; маркеры `unit` (без Docker/сети) и `integration` (со стеком, skip с понятной причиной); зависимости инъектируются, composition root — точка подмены. Порог покрытия фиксируется и enforced в гейте закрытия сессии.
8. **Деградация вместо падения:** недоступность зависимостей — понятный код/статус (503/`degraded`), а не 500; security-стыки — fail-closed (зависимость недоступна → отказ, не «пропустить»).
9. **TTL и лог:** потенциально зависающие команды (сборки, тесты, инжест) — только с таймаутом и выводом в лог-файл вне git; после прогона — код возврата и хвост лога.
10. **Версионность:** свои сервисы тегируются осмысленной версией (`IMAGE_TAG`), деплой на `latest` запрещён; сторонние образы пинятся на конкретную версию — без floating-тегов.
11. **Беклог:** всё обнаруженное вне скоупа сессии — в `solution/backlog.md` (формат — `solution/README.md`); то, что влияет на приёмку сессии, остаётся в сессии.
